- The bell counts new mail in one row. It used to list every new letter, which made the centre a second inbox; now it says "10 new messages" and nothing else: no sender, no subject, no account. The count grows and the row rises while it stands unread, and it is read when you press it, open Mail any other way, or mark everything read; the next letters after that open a new row from one. Push on the phone is unchanged, one per letter. Rows from before the upgrade fold into one on the first read.
- Next.js 16.3.5. The 16.2 line carried two critical advisories, one of them an unauthenticated remote code execution in the image optimiser, a route Brain never used but served; it is closed at the edge on the reference host and gone with the upgrade. The transitive floors move with it (nodemailer, fast-uri, js-yaml, deepmerge-ts, browserslist, hono, qs): `pnpm audit --prod` reports no critical, high or moderate finding.
- Every MCP tool declares the protocol's annotations: whether it only reads, whether it can destroy, whether a repeat is safe, and whether it reaches beyond Brain, so a host can ask before `delete_page` or `send_mail` and pass a read without a prompt.
- A task made, ticked or deleted in a note shows up where tasks are read. The editor kept the answer to its own promote and reschedule, so Tasks, Home's Today block and the sidebar count went on showing the old list until a reload or midnight; they read the shared set now, and a note save that touches a task line re-reads it once. The MCP `search` tool answers a ripgrep failure as `search_backend` rather than as the notes folder failing.
