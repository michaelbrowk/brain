- An agent can build an app inside Brain. Ask Claude for a trainer for the Spanish words you are learning and it makes a page whose body is an application rather than text: open it and it runs, in the same window as your notes, with the sidebar, the head, Share and pin around it. You cannot edit it in the editor; you ask the agent for changes, and a Rebuild control copies that request for you. Every place a page is named, an app page carries a small AI mark, so you always know which pages a person wrote and which an agent built.
- An app runs in a sealed frame. It has no network, no cookies, no way to reach Brain's own address or the window it sits in. Everything it knows about your notes arrives through one narrow door: it may read the whole notebook, it may write only the pages it made, and every write shows in the bell ("Trainer updated Words") and in Settings › Connections. The rules, and how to build one, are in docs/apps.md.
- An app is the last resort, not a shortcut. The tool that builds one says so to the agent in as many words: build an app only when the owner asked for one, or when what they asked for cannot be done with a page, a table, a checklist, tasks, mail or a collection view, and say so before building. The agent has to pass the owner's own request in one line, and it stays on the page under "Built by".
- Apps follow the theme. An agent gets Brain's design tokens and a small kit of controls; the entry is refused before it is written if it hard-codes a colour, loads anything from another site, or ignores the dark theme.
- The first app ships as the example: a Spanish word trainer that reads the words from every page under its parent, keeps a "Words" page with a status per word, shows a card with three answers, and stops showing the words you know. Correct a translation on the Words page by hand and the trainer keeps your correction; it owns only the schedule. It is in examples/apps/spanish-trainer.
- An app page can be shared like any page. A visitor runs it read-only: it sees only the shared subtree, it cannot write, and its progress stays in that visitor's own browser.
- Portable archives are format 3 and carry an app's files. A format 2 archive imports unchanged; a format 3 archive does not open in an older Brain.
- Three things I know about. The lint stops the two failures that break the theme and nothing more: a colour assembled at runtime gets past it. The frame's address carries a signed key that lives twelve hours, so a copied address or a browser history holds it that long; it opens that one app's files and nothing else. And an install without HTTPS has no MCP endpoint at all, which was already true; the app tools are covered by their own tests, and the browser test builds its app through a portable import instead.
