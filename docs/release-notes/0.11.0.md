- Claude can work your mail now, through the same MCP connection it already uses for your notes. One server, one consent screen, and behind it your mail, your tasks and your pages. Until this release an app you connected could read and write notes and nothing else.
- Two new lines appear on the consent screen: "Read and sort your mail" and "Send mail as you". Mail is a second axis rather than a step above writing, so an app you give mail to cannot edit your notes, and a read-only app gets neither. One thing to know before you upgrade: a connection you already approved with write access reaches mail without a new consent screen, sending included, because Brain widens any owner write grant to everything it offers. If that is not what you want, Settings, Connections has two switches and a Revoke button, and the switches are the light answer.
- It reads every account you have connected. List a mailbox, open a thread, read the words of one message, and search. A search with no account named runs on all of them at once and merges the results newest first behind one cursor, which is the thing the app itself does when you open the unified inbox. Bodies come back as text, never as HTML, in either direction.
- It sorts as well: read, unread, star, archive, trash, spam, and restore out of trash or spam. One change per call, which is the shape the mail service's own PATCH takes. There is no purge and no empty trash, so anything an agent throws away is still in your trash when you look. Marking a thread read also clears its row in the notification centre, the way reading it in Mail does.
- It can send. You name the account on every send, every send needs its own idempotency key so a retry cannot put a second copy on the wire, and the body is text, the way the composer already is. A reply works its recipients out from the message it is answering, with the same rules the app uses, and refuses to take a recipient list from the agent at all. If a send times out, the tool says "unknown" rather than "refused", and tells the agent to ask again with the same key, because the mail service holds the message durably before it delivers and a fresh key would send it twice.
- Every message an agent sends is marked, in three places you can see and one you cannot. The message carries an `X-Brain-Agent: mcp` header you can filter on. The row in your Sent mailbox reads "Sent by ‹app›". One line lands in a new activity log. Nothing is added to the body unless you turn on "Tell recipients when an agent writes", which is off, and which adds one last line reading "Sent by an agent through Brain.".
- Settings, Connections has a new block. The last fifty things agents changed, one row each, with a Clear button, and two switches: whether recipients are told, and whether agents may send at all. Sending is on by default, and turning it off refuses `send_mail` and `reply_mail` before the mail service is touched while reading keeps working. A switch Brain cannot read refuses sending rather than falling back to on. The log holds ids, tool names and outcomes, and never a subject, an address, a body or a title. It lives beside your OAuth state under `/var/lib/brain`, not in your notes folder, so git never sees it and no backup carries it.
- Every grant now names everything it can reach. A connection made before this release stored the words "Read, Write", and the screen showed those words while the code was already giving it more. It reads "Read · Write · Import · Mail · Send mail" now, which is the truth about what that token opens.
- Attachments go both ways. An agent can save a file out of a message straight into a note, with an image shown or a link added to the page, and it can attach a file to a message it sends. It can only attach a file the note it names already shows, which is exactly what you could do by opening that note and forwarding it yourself. A file a message hands over is refused if its name would end in an executable extension, whatever type the sender claimed for it, because a remote sender chose those bytes and an agent chose to keep them.
- An outgoing message can carry 10 MiB of files across at most ten of them, up from a request limit of roughly 1 MiB that fitted no attachment at all. The number is set by memory rather than by what a provider would take: the mail service runs under a 256 MiB ceiling, a single 10 MiB send was measured taking most of the room under it, and it builds one message at a time so two large sends cannot overlap. Brain waits its own turn above the socket for the same reason. One caveat, and it is a real one: an IMAP account sends through the Cloudflare relay, whose tunnel is capped at 2 MiB, so a large attachment from an IMAP account is refused at the relay until that budget moves. Gmail accounts are unaffected.
- Agents own tasks now. Create, reschedule, categorise, repeat, complete, reopen, delete, and turn a `- [ ]` line in a note into a task with the same anchor the editor's own gesture builds, inheriting the note's category the same way. The old rule was that an agent wrote a checkbox line and you promoted it. You asked for the other thing, and this is it.
- The task tools speak your clock. A task can be given a time and an evening, the two fields 0.10.4 added, and a completion needs the caller's own calendar date because it files a day into the Logbook. For reads, an agent that does not know your date can leave it out and Brain uses the time zone Settings, Account holds. With no zone captured the read is refused rather than answered in UTC, which would put half your day in the wrong list.
- `list_tasks` takes a `page` and answers every record that note owns, whatever state it is in, so an agent can see what is already there before it adds another.
- Every tool Brain offers is now written down, in `docs/mcp-tools.md`: what it takes, what it answers, the scope it needs and the exact words of every refusal. There has never been such a page.
- Four things I know about and did not finish. A reply an agent writes into a thread that still holds an older unread message can make the bell ring naming the person it was answering, about words the agent wrote, because the gate Brain has is "something in this thread is unread" and the exact one lives in the mail service. A draft still cannot carry an attachment, and the composer still has no attachment button, although the whole send path underneath it is ready. A message sent from an IMAP account never gets the "Sent by" caption on its row, because the caption joins on a thread id only a provider delivery hands back, while the header and the log line are there as usual. And a read is never logged: Connections shows what an agent changed, never what it looked at.
